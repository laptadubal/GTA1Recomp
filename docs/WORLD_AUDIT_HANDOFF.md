## 2. Ключевые факты Формата (проверены по байтам)

### MapBlock — 8 байт (src/data/formats.h)
```
+0 typeMap: u16   bits 4-6 blockType, bit7 flat (128), bits 8-13 slopeType (0..44)
+3 typeMapExt: u8 bits 3-4 remapIndex (0-3), bit5 flipTB (32), bit6 flipLR (64)
+4 left, +5 right, +6 top, +7 bottom  (u8, 1-based tile id, 0 = нет)
+8 lid? -> НЕТ: порядок (ty,ext,l,r,t,bo,lid): +4 L +5 R +6 T +7 B, lid = 8-й байт записи
```
Колонка: `base = u32[28 + x*256+y]`; `bi = base/2`; `n = 6 - column[bi]`;
блок z: `column[bi + n - z]` (z=0 — низ). Объекты: 14 байт, offset `28+65536*4`,
количество `= objectPosSize/14`; x/y/z — fixed 8.8.

### Статистика flat-блоков (все 3 города, /tmp/flat_audit.py)
- NYC: 11041 flat; MIAMI: 9324; SANB: 7938.
- **Поля строго парные: L==R — 100% случаев, T==B — ~100%**. «Одиночные» поля практически не
  существуют (только 2 шт. onlyR в NYC). Вывод: пара = ОДНА текстура на ОДНУ плоскость.
- Частые side-тайлы flat-блоков: NYC 190 (забор, 2144×), 46/51/55; MIAMI 101 (2836×),
  106, 124, 70; SANB 188/112/160.
- NОN-flat кубы — поля НЕПАРНЫЕ (например (134,118,2) MIAMI: L164 T164, R=B=0) — каждая
  грань у куба самостоятельна.

## 5. Сопоставление с OpenGTA (tools/OpenGTA/gl_cityview.cpp, drawBlock, строки 661-1420)

OpenGTA = сторонняя реализация, НЕ абсолютный эталон, но ценный ориентир.
- **Осевая раскладка НЕ транспонирована**: `glTranslatef(x, 6.1f - z, y)` (строка 643) —
  map x→world x, map y→world z, как у нас.
- Таблица граней (slope 0): 0=LID, 1=NORTH(z=1), 2=SOUTH(z=0), 3=WEST(x=0), 4=EAST(x=1).
- **Non-flat**: top→face2 (пропуск при slope=42), bottom→face1 (41), left→face3 (44),
  right→face4 (43). texSet: top=1, bottom=0, left=2, right=3; MSWAP(0,2)/(4,6) по flip-флагам.
- **Flat-ветка**: обрабатывает только `lid`, `top`, `left`. `top` → face2 + face1 (со сдвигом
  −1.001, т.е. одна двусторонняя плоскость на ЮЖНОМ краю z=0); `left` → face3 + face4
  (−1.001 по x; плоскость на WEST x=0); `right`/`bottom` **игнорируются**.
  ИТОГО: пара → одна двусторонняя декal-плоскость на конкретном краю.
- **OpenGTA НИГДЕ не заменяет отсутствующие текстуры соседей**: `if (bi->left)` — рисуем
  только когда поле ≠ 0. (Дока для пункта C задания.)

### ⚠ РАСХОЖДЕНИЕ 90°, требующее разрешения
Наш faces[] (world.cpp ~строка 465): north(z=0)=«left», south(z=1)=«right», west(x=0)=«top»,
east(x=1)=«bottom» — т.е. left/right → КРАЯ ПО Y, top/bottom → КРАЯ ПО X.
У OpenGTA: top/bottom → КРАЯ ПО Y (z), left/right → КРАЯ ПО X. **Перпендикулярно друг другу.**
Кто прав, пока не установлено. Проверка: NYC-забор 190 — в оригинале пикетные заборчики стоят
вдоль улиц; определить ориентацию ряда 190-блоков в CMP (вдоль X или Y) и сверить со
скриншотом. Либо через режим `idcolor` (§6.1) + кроп NYC.
