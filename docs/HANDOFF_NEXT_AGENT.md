## 0. TL;DR

Найдена и исправлена **фундаментальная ошибка: вся карта читалась
транспонированной** (зеркально отражённой относительно диагонали). CMP-сетка
`base` хранится column-major — `base[y * 256 + x]`, — а движок читал
`base[x * 256 + y]`. Город при этом оставался «похож на город», поэтому баг жил
очень долго: улицы, дома и вода были на месте, но весь рисунок был зеркальным,
а все авторские привязки (телефоны, объекты, маршруты) оказывались разбросаны
относительно геометрии. Это и есть главная причина «не похоже на оригинальную
GTA 1».

Коммит: **`7b43564`** — `world: read the CMP base grid the right way round (city was transposed)`.

## 2. Что именно поменялось в `world.cpp`

Поля блока описывают грани куба, и после исправления сетки они читаются
«как написано»:

* `left` / `right` — грани, перпендикулярные **X** (`x = 0` / `x = 1`);
* `top` / `bottom` — грани, перпендикулярные **Z** (`z = 0` / `z = 1`).

Это ровно та таблица, что в OpenGTA `drawBlock` (`top` → грань `z = 0`,
`bottom` → `z = 1`, `left` → `x = 0`, `right` → `x = 1`); texSet: top=1,
bottom=0, left=2, right=3. Прошлая таблица была транспонирована
(`left/right` → края по Z, `top/bottom` → края по X) — именно это описано в
§5 старого хендоффа как «расхождение 90°, требующее разрешения». Вопрос
**закрыт**: прав OpenGTA, расхождение было следствием транспозиции сетки.

Плоские декали (заборы/перила) в старой ветке были перепутаны местами; теперь:

* пара `top`/`bottom` → вертикальная плоскость на ребре `z = 0`;
* пара `left`/`right` → плоскость на ребре `x = 0`.

(OpenGTA рисует ровно одну двустороннюю плоскость на этих же рёбрах.)

## 3. ГЛАВНАЯ НАХОДКА ДЛЯ ПУТЕЙ МАШИН: в CMP есть оригинальная сеть маршрутов

В CMP после блоков и объектов лежит **route network** — `routeSize` байт
(`NYC 2423`, `SANB 3576`, `MIAMI 4416`). Формат (проверен побайтово,
парсится до конца во всех трёх городах):

```
repeat:
  u8 num_vertices
  u8 route_type
  num_vertices * (u8 x, u8 y, u8 z)   // мировые координаты клетки, z = высота
```

* `route_type == 255` — **пешеходные** петли (NYC 22, MIAMI ?, SANB ?);
* `route_type == 0..28` — **автомобильные** маршруты (по одному на тип);
* `route_type == 254` — только NYC, единственный маршрут, 20 вершин, 19/20 на
  дороге — очень похоже на **эстакадную железную дорогу / train**;
* последняя вершина маршрута — терминатор `(0,0,0)`; полилиния замкнута
  (первая точка повторяется перед терминатором);
* соседние дублирующиеся вершины — норма (переход между сегментами);
* **координаты в исправленном фрейме**: `(x, y, z)` → клетка `(x, y)`, без
  перестановки. Это и было вторым доказательством ориентации.

**Движок эту сеть не использует вообще.** Трафик сейчас — самодельный
клеточный AI: `Game::spawnTraffic()` / `updateTraffic()` в `src/core/game.cpp`
(~2976–3227). Машины едут от центра клетки к центру клетки
(`car.pos = target`), то есть **по осевой линии**, и разъезжаются только за счёт
`blockedBy()`. Отсюда «пути машин очень плохо»: нет полос, нет оригинальных
маршрутов, повороты 90° на перекрёстках «наугад».

План (по возрастанию объёма):

1. Распарсить маршруты в `CityMap` (`std::vector<Route>`), см. готовый разбор в
   `tools/audit_map_orientation.py:routes()`.
2. Трафик: спавнить машины **на** car-маршрутах рядом с игроком, вести по
   полилинии, на терминаторе — либо замыкать петлю, либо переключаться на
   другой маршрут (в оригинале маршруты — связная сеть с узлами).
3. Полосность: смещать позицию от осевой на перпендикуляр к направлению
   движения. GTA1 — **левостороннее** движение (DMA, UK): при движении вдоль
   `+X` держаться `-Z`. Проверить по оригиналу и вынести сторону в константу.
4. Пешеходы: `route_type 255` для прогулок по тротуарам — сейчас пешеходы
   блуждают случайно (`spawnPeds`/`updatePeds`).

## 5. ОТКРЫТЫЕ ЗАДАЧИ (по приоритету)

### A. Ротация lid — вероятный остаток транспозиции (САМОЕ ВАЖНОЕ)
Формула в `world.cpp:emitLidUV`:

```cpp
const int k = (4 - rotation - j) & 3;
```

Это **поворот, скомпозированный с отражением** (`j → -j`), то есть ровно то,
что нужно для транспонированного фрейма. Теперь, когда сетка исправлена,
формула, скорее всего, должна стать **чистой ротацией** (`k = (rotation + j) & 3`
или `k = (rotation - j) & 3`). Симптом: в MIAMI на `--spawn 122,128` дорога
выглядит «пятнисто» — короткие жёлтые поперечные штрихи, которые не стыкуются
между клетками, тогда как в NYC на `--spawn 108,108` разметка читается
нормально. В `tools/audit_map_orientation.py` есть всё для быстрой проверки;
для визуальной — рендерить тайл-пиксели top-down (скрипт-скелет см. в истории
сессии: клетка, билинейная интерполяция UV по углам `j0(0,1) j1(1,1) j2(1,0)
j3(0,0)`), варианты `cur/neg/revj` и сравнивать стыковку разметки.

Ориентир: OpenGTA, `gl_cityview.cpp` — `jj = 0; if (typeMap & 16384) jj += 2;
if (typeMap & 32768) jj += 4;` и далее `SLOPE_TEX_CP`/`GLTEX_HELPER`
(у нас `rotation()` = `jj / 2`).

### B. Звук — сейчас синтетический, банк выбран неверно
* `src/main.cpp:213` **жёстко грузит `AUDIO/LEVEL001.SDT`** для всех городов.
  Правильно: `LEVEL001` ↔ style 1 (NYC), `LEVEL002` ↔ style 2 (SANB),
  `LEVEL003` ↔ style 3 (MIAMI). Банк надо выбирать по `map.style`.
  (`LEVEL000` — 16 записей, спектр похож на белый шум, в игре, судя по всему,
  не используется: города 0 не существует.)
* **Двигатель синтезируется синусом** (`AudioManager::mix`, `baseFreq` и т.д.).
  Оригинальные loop-сэмплы двигателя найдены и опознаны: это записи
  **`id = 79 + car.sprNum`** (диапазон 79..125). Признаки: `edge ≈ 0.00–0.04`
  (бесшовная петля), все на 5500 Гц, узкие тональные пики (1225 Гц, 1696 Гц,
  575/848 Гц, 1252 Гц), `env` стационарная. Записи 79..99 идентичны во всех
  трёх банках, 100..125 — город-специфичные, что точно совпадает с тем, что
  `sprNum 0..20` — общие машины, `21..28` — городские. Формула `79 + sprNum`
  даёт максимум 107 — внутри диапазона.
  Играть как зацикленный сэмпл с питчем от скорости (`rate/sampleRate * pitch`),
  синтез оставить как fallback.
* `playSfx(id)` в `game.cpp` использует id 12/13/14/19/37/39/43/44/49/53/56/59/66.
  Их соответствие оригиналу **не подтверждено** — это предположения прошлых
  агентов. Проверяемых таблиц id в `GTA8.EXE` нет (только `GUN_TRIG`,
  `EXPLODE` в SETSOUND-скрипте). Если возьмётесь — сверяйте по спектру/длительности.
